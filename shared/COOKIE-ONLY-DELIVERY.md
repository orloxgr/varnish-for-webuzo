# Observed server cookie delivery on cached public parents

A Shared cookie action approves sharing the public HTML across its values. It
cannot execute an application issuer on its own. A publication that actually
observed a real source `Set-Cookie` may declare `X-UltraCache-Cookie-Delivery: 1`
only after the application approves the public body and negotiates native
`X-UltraCache-VCL-Cookie-Delivery-Version: 1` through its normal capability test.
No issuer name/value, consent grant or browser identifier is generated by native.

The application binds `cookieDelivery: true` into its existing signed manifest
and locator. The public parent retains only that boolean work declaration, its
signed `X-UltraCache-Delivery-Prepare` pointer, and its actual private-slot count.
There is no synthetic ESI occurrence. An observed-issuer publication may have
`X-UltraCache-ESI-Private-Count: 0` and an empty fragment array.

On a marked public-parent HIT, native executes one original-route private
prepare. It forwards the flag from owned continuation state, the original Cookie
and existing request/URL/manifest/authorization binding. The application executes
the real producer lifecycle and actual consent decisions, then returns original
provider fields and a bound schema1 envelope with strict `cookieDelivery: true`.
An empty fragment array is accepted only for this explicitly marked, bound
operation. Existing unmarked classic fragment envelopes remain unchanged.

Public selection may likewise include strict `selectedPublic.cookieDelivery:
true`, a matching single marker header and its signed prepare pointer. Native
validates marker/count/manifest/body/coverage together before accepting a public
snapshot. Missing, duplicate, string/false flags, mismatched headers and incomplete
coverage fail rather than claim verified delivery.

Real Set-Cookie fields remain request-owned: create, renew, delete, duplicate
names at different paths and original attributes are delivered only to that
visitor. They never become public object metadata. Provider failures retain the
existing degraded/error/private-document semantics. Request-owned
`X-UltraCache-Delivery-Outcome` reports verified/degraded/unverified independently
of Debug. The nonsecret final `X-UltraCache-Cookie-Delivery: 1` flag lets warm-up
require that outcome for cookie-only pages too. Browser copies cannot start an
operation; native removes them at ingress. Downstream delivery is private/no-store.

A marked HIT deliberately incurs the actual application issuer's PHP work while
reusing its cached public parent. An unmarked plain warm HIT retains zero backend
work. This supports observed, integrated producer lifecycles; it does not promise
an arbitrary unobserved future issuer will run, and it adds neither a universal
cookie generator nor a provider allowlist. Basic never enters this continuation.

Native mock transport tests and portable real-C grammar tests are separate from
actual WordPress/provider/browser lifecycle qualification. The application must
verify template/footer/shutdown timing as applicable and publish accurate cost
and acceptance results.

## Existing publications after an upgrade

An old unmarked cached publication does not prove its source issued a cookie.
Its plain HIT remains zero-backend until normal application republication. After
updating both compatible components, use normal capability redetection, clear
old application cache and warm the desired pages. The application's optional
purge-after-plugin-updates setting is not assumed to be enabled. No unconditional
production purge or cookie-name inference is added by this native contract.
